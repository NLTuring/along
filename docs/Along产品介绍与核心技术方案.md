# Along 一起游 · 产品介绍与核心技术方案

> 面向国内外游客的 AI 旅行陪伴与影像文创平台

---

## 一句话介绍

Along 一起游是面向国内外游客的 AI 旅行陪伴平台：攻略已经过剩，陪伴仍然稀缺——外国游客缺语言与带路，国内游客缺同质化之外的新鲜体验。核心技术是用一张照片生成可打印的 3D 记忆：AI 分割人物、用户涂抹确认，手机端参数化生成毫米级闭合网格，导出 GLB/STL 并可直接下单实体文创，同一条链路让照片变成可旋转分享的三维记忆。行程、同游、影像、文创四段串成闭环。

---

## 一、产品介绍

### 1.1 市场判断：两个市场，一个结构性问题

入境游与国内游看起来是两门生意，卡住游客的却是同一件事。

**入境侧**：240 小时过境免签适用国家增至 57 国、可从 65 个口岸入境；2026 年三季度外国人入境 1160.1 万人次，同比上升 15.6%，其中免签入境 899.2 万人次，占 77.5%。政策解决了「能来」，没解决「来了怎么玩得好」。

**国内侧**：出行人次基数远大于入境，但供给高度同质化——同一批网红点位、同一套滤镜、同一份榜单。游客的真实反馈是「攻略看了三十篇，到了还是不知道今天该干嘛」。

两边叠在一起，是同一个结构：**信息过剩而判断稀缺，内容过剩而陪伴稀缺，照片过剩而记忆稀缺。**

### 1.2 用户痛点

| 阶段 | 外国游客 | 国内游客 |
|---|---|---|
| 出发前 | 看不懂中文攻略，不知哪些点值得去、要多久、周几闭馆 | 攻略同质化，难以按自己的体力、预算、兴趣排出真实可走的行程 |
| 落地后 | 语言不通、支付不便、无人带路，第一天最慌 | 到了现场才发现排队、闭馆、下雨，缺少可即时调整的方案 |
| 旅途中 | 问路、点菜、讲价都要靠翻译软件逐句拼 | 想要有人一起走、有人讲、有人拍，独自出行尤其明显 |
| 归来后 | 几十张照片散在相册，讲不出故事，也带不走 | 发完朋友圈就结束，没有可长期留存的实物或作品 |

### 1.3 产品定位

**Along = 行程引擎 + 同游网络 + 影像文创**，一个 App 走完一次出行的全周期。

三个关键词，对应三个真实动作：

- **落地有人接** —— 按城市、时段、兴趣匹配本地伙伴：志愿者陪同（免费，只陪不讲解）与持证导游（付费讲解）两类身份分开标注，不越资质边界。
- **同游有得玩** —— 输入到达时间、城市、天数、兴趣与体力，生成 3/5/7 天可执行行程；时间轴、站间交通、营业时间检查、雨天备选、费用合计一次给全。
- **回国带得走** —— 一张照片生成 3D 人物浮雕冰箱贴或钥匙扣，可 360° 旋转、可下载 GLB/STL、可直接下单实体制作。

### 1.4 四段旅程

```
出发前 ────────── 旅途中 ────────── 归来后 ────────── 带走
行程生成           地图与同行          故事与短片          3D 文创
到达时间/天数      路线/伙伴/助手       社区/审核/收藏      浮雕建模/下单
```

**出发前**：到达时间、城市、天数、兴趣、节奏、预算六项输入，生成分天行程。每站带停留时长、门票、开放时间、交通方式；落在闭馆日或营业时间外会标红。

**旅途中**：地图与行程共用同一条路线，改目的地即重排后续站点；道路计算失败时退回地点顺序示意，不阻塞出行。同游伙伴按城市、类型、兴趣筛选，可约时段、可私聊确认协助范围。AI 助手「小游」负责问路、翻译、推荐，能把结果一键交给司机看。

**归来后**：照片进入数字藏品，可三维翻面写回忆；社区发帖先审后发，示例内容与用户内容严格分离。

**带走**：选一张照片，选冰箱贴或钥匙扣、四种外形，生成可打印的浮雕模型，或进入人工制作询价。

### 1.5 服务谁

| 角色 | 诉求 | Along 提供 |
|---|---|---|
| 外国游客 | 语言、路线、可信信息、本地人 | 中英双语界面、AI 翻译、志愿者/持证导游 |
| 国内游客 | 个性化行程、同行者、可留存的记忆 | 兴趣与体力驱动的行程、同游撮合、3D 文创 |
| 本地伙伴 | 有组织的陪伴机会与被记录的付出 | 身份分层、时段管理、服务记录 |
| 文旅与商家 | 可复用的内容与增量订单 | 城市内容库、文创制作履约、数据看板 |

### 1.6 差异化

1. **不是 OTA**：不卖门票酒店，卖的是「今天怎么走、和谁走、走了留下什么」。
2. **不是地图**：地图只回答距离，Along 回答「这段路我能不能走完、累了在哪坐」。
3. **不是修图软件**：照片的终点不是滤镜，是一个能打印、能下单、能摆在桌上的物体。
4. **陪伴与文创双引擎**：陪伴带来使用时长与信任，文创带来客单价与复购，互为入口。
5. **边界写进产品**：不承诺无障碍认证、不做逐步导航、不做医疗与救援，把能做的做扎实。

## 二、核心技术方案

### 2.1 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│ 体验层  Web 端（手机适配）· Android 壳 + WebView · 管理端     │
│         行程 / 地图 / 同游 / 社区 / 助手 / 文创 / 短片        │
├──────────────────────────────────────────────────────────────┤
│ 接入层  同源 API 网关 · 会话鉴权 · CSRF/Origin 校验           │
│         邮箱验证码登录 · 匿名设备身份 · 角色与权限隔离        │
├──────────────────────────────────────────────────────────────┤
│ 服务层  行程服务 · 匹配服务 · 社区服务 · 媒体服务             │
│         助手服务 · 建模任务 · 询价订单 · 管理审核             │
├──────────────────────────────────────────────────────────────┤
│ AI 层   行程排程内核 · 人物分割 · 图像风格化                  │
│         受控对话（闭集动作）· 浮雕参数化建模 · 网格校验       │
├──────────────────────────────────────────────────────────────┤
│ 数据层  PostgreSQL · Redis 队列 · 私有对象存储 · 内容库       │
├──────────────────────────────────────────────────────────────┤
│ 交付层  Docker Compose · Nginx · HTTPS · 静态站点 · APK       │
└──────────────────────────────────────────────────────────────┘
```

一条贯穿全局的原则：**确定性的写在代码里，不确定的交给模型，模型的结果必须可校验。**

### 2.2 关键技术 A：AI 行程引擎

**不是「让大模型写一份行程」，而是「约束求解内核 + 模型理解偏好」。**

- **输入解析**：用户自然语言（"想慢慢逛、走不动太多台阶、预算别太高"）由模型抽取成结构化偏好向量（兴趣权重、体力档、预算上限、节奏）。
- **约束建模**：把地点库写成带属性的节点——开放时间、闭馆日、停留时长、门票、坐标、台阶与休息点标记。
- **排程内核**：按天做带时窗的路径搜索。硬约束（营业时间、到达时刻、交通时长）先过滤，软约束（兴趣重合度、绕路成本、体力衰减、雨备选匹配度）加权评分，取可行解中最优组合。
- **可解释输出**：每站附带「为什么是这里、为什么这个顺序、下雨怎么办、大概花多少」，用户看得懂才敢照着走。
- **实时重排**：途中改一站，只重算受影响的后序片段，不推翻整天。

内置地点库按城市组织，新增城市只需补一份带属性的 POI 数据，不改内核。

### 2.3 关键技术 B：同游匹配

双边匹配问题，两边都是活人，所以安全和可退出比「匹配得准」更重要。

- **硬约束过滤**：城市、时段交集、语言、身份类型（志愿者 / 持证导游）。
- **软约束打分**：兴趣重合度、路线重合度、距离、历史履约率、评价分。
- **安全设计**：志愿者与持证导游身份分层展示；预约走状态机（申请 → 确认 → 开始 → 完成 → 评价/取消），超时自动过期；行程可只读分享给家人；紧急联系常驻。
- **边界**：只做撮合与记录，不替代专业照护、医疗与救援。

### 2.4 关键技术 C：单图 3D 人物浮雕（核心突破）

这是整套方案里最难、也最不可替代的一段：**把一张普通照片变成一件有真实厚度、可被标准切片软件读取的物体，而且全程在手机上完成。**

```
选图 → 人物分割 → 用户涂抹确认 → 轮廓提取
     → 参数化浮雕建模（mm）→ 网格校验 → GLB / STL → 实体制作
```

**① 分割与确认**
AI 返回人物检测框与轮廓多边形，服务端做几何校验：边界越界、自交、点重复、置信度过低一律退回。**AI 只给建议，用户涂抹决定哪块凸起**，界面明确标注「手工选择 / AI 建议」，不冒充完整人体扫描。

**② 风格化**
可选把照片重绘为动漫或水彩风格用于正面贴图，原图始终保留，两种风格可随时切换。

**③ 参数化浮雕建模**（`mobile/assets/js/craft-geometry.js`）
以毫米为单位建模，不是把平面图案贴到方块上：

- 按产品（冰箱贴 / 钥匙扣）与外形（圆角 / 椭圆 / 拱形 / 花边）生成板体轮廓；
- 人物区域按 **chamfer 距离场**做倒角凸起，背景保持平面——凸起有真实高度，不是灰度位移；
- 冰箱贴留磁铁槽（深 1.2 mm），钥匙扣留挂孔（半径 2.5 mm）；
- 正面 UV 贴图承载照片，背面闭合平直；
- 对角线消歧处理，保证离散化边界是真正的流形墙，不产生仅靠对角相接的破面。

**④ 校验与导出**
每件模型逐项校验：顶点与索引合法性、退化三角形、**每条边必须被恰好两个三角形反向共享（流形闭合）**、有向体积为正。通过后导出 GLB（含纹理，米为单位）与 STL（纯几何，毫米），可被标准 GLTFLoader / STLLoader 重解析。

**⑤ 实体履约**
模型进入询价单，冻结版本号；报价用整数分、由服务端计算；确认后进入制作 → 发货状态，开始制作后拒绝在线取消。

### 2.5 关键技术 D：受控 AI 助手

旅行场景里，编造一个营业时间就可能让用户白跑一趟，所以助手的能力边界是产品的一部分。

- **闭集知识**：只从已核实的地点库、伙伴库取事实，不在库里就明确说没有可信信息。
- **闭集动作**：模型只能输出白名单内的动作（打开某页、跳转某地、发起导航、筛选伙伴、复制译文），服务端二次校验 id，不在白名单一律丢弃，绝不猜测。
- **受控提示**：系统提示约束回复长度、语言、紧急情况直接给 110/120，拒绝越权指令与提示词泄露。
- **多语言 + 语音输入**：语音受限时自动退回键盘，不让用户卡在权限弹窗上。

### 2.6 关键技术 E：双语与适老

- 全量文案 key 化，中英各一套，构建期检查 key 与占位符是否一致，缺一条即失败。
- 适老是独立开关，不是换皮：导航收敛为三个入口、字号与操作区放大、默认关闭智能生成入口、降低动效与透明度、低内存设备自动降级玻璃效果。

### 2.7 关键技术 F：影像与社区

- 视频上传 → 队列转码 → 生成封面 → READY，播放支持 Range 请求。
- 内容先审后发，审核前仅作者可见；点赞幂等、评论分状态、举报可写入。
- 私有媒体与模型按作者鉴权，对象存储不开公开桶。

### 2.8 一张照片的完整数据链路

```
用户照片
  → 净化与重编码（去元数据、限尺寸）
    → 人物分割 / 手工涂抹 → 掩膜
      → 浮雕参数化建模（mm）
        → 流形与体积校验
          → GLB（纹理）/ STL（几何）
            → 手机端 360° 查看 + 下载
              → 询价 → 制作 → 实体文创
                → 3D 记忆馆（网页端展陈、可分享）
```

### 2.9 工程与安全

- **测试**：前端与服务端各一套自动化用例，覆盖行程状态机、预约过期、几何校验、导出、权限隔离；三账号真实 HTTP 联调验证越权不可读；双语文案一致性单独检查。
- **外部调用**：只走 HTTPS 443，精确域名白名单，拒绝重定向与凭据 URL，DNS 全解析并拒绝内网/回环/保留地址，结果图按白名单下载且不回传密钥。
- **配额与成本**：按账号与服务双维度日限额，后台并发受限，超时即失败而不是假装成功。
- **数据**：数据库、队列、私有对象存储均不暴露公网；生产禁止开发模式与验证码明文显示。

## 三、演进方向

1. **行程引擎做实**：从模板走向真正的约束求解排程，支持多城、多日、体力档与实时天气重排。
2. **同游网络做实**：伙伴身份与资质审核、履约评价、双向确认，把撮合从演示做成可运营的服务。
3. **文创供应链做实**：云端建模任务、报价与工单、物流状态，把「可下载模型」变成「可收到的实物」。
4. **多城复制**：以城市为单位打包内容与伙伴供给，跑通一座再复制下一座。
5. **体验增强**：AR 预览成品摆在家里的样子、三维记忆馆的社交化展陈、短片模板与自动剪辑。

## 四、边界

- 不做逐步导航，不声称已完成无障碍路线认证，点位信息需结合现场确认。
- 不做自动危险识别、救援调度与医疗监测，专业照护与应急另行安排。
- 数字藏品是照片、文字与创作作品，不涉及代币或交易。
- 三维文创是设计示意与可打印几何，实体成品需结合材质与工艺打样确认。
- 志愿者只陪同、不讲解；讲解由持证导游提供，两类身份不混用。
