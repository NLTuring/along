# Along 手机端与线上服务工程

当前版本已实现百度地图接入页、服务端登录与共享社区、视频上传转码、真实三维人物浮雕及 GLB/STL 导出、人工制作询价和管理端。**尚未正式上线**：当前启动的是仅本机开发服务；浏览器/服务端百度 AK、AI 模型/分割服务、邮件、云存储、生产数据库和部署域名仍需配置与联调；Android AK 的打包接入见下文。

展示品牌为 Along，保留旧 `instrip.*` 存储键和照片 ID。旧行程、向导预约、伙伴申请、照片轮播短片等仍是本机功能，不因新增社区后端而变成真实预约/支付服务。旧本机登录状态不会被当作线上身份。

**已另行生成 Android 百度原生地图测试包**：`_build/along-android-baidu-test.apk`，已注入用户提供的 Android AK 并沿用确认的测试签名。详见 [安装与验证说明](../_build/Along-Android地图安装说明.md)。尚无真机或 Android WebView 运行验收。网页 GLB/STL 下载已验证，旧原生 `exportImage` 仍只是图片通道，不能据此宣称 APK 可以保存三维文件。

Android 地图页复用已验证的 `Android.setMap` / `getLocation` 协议，使用 BD-09 坐标、隐私同意流程、就绪/鉴权事件及限定透明区域；浏览器仍走独立 Web 地图路径，不混用 AK。线上后端未部署，APK 不会自动连接电脑的本地开发服务。

## 文创工坊：积分、拼豆、捏泥、画廊（2026-11-24）

入口：底部相机按钮 → 「做一件纪念品」，或「我」→「文创工坊」。路由 `#/workshop`、`#/points`、`#/beads`、`#/clay/new`、`#/gallery`。

**合并重复入口（2026-11-24 第二轮）**：「我」页原来分开列着「我的纪念品」「工坊积分」「制作与邮寄」，现在只留一个「文创工坊」；工坊首页下方的「我的工坊」统一列出冰箱贴与钥匙扣、我的画廊、制作与邮寄、拼豆材料包、积分。「我」页也去掉了和行程页重复的「我的行程」「地图与导航」。这些页面的返回都回到工坊。旧链接 `#/crafts`、`#/make-orders`、`#/points` 仍然可用。

- **积分**（`js/points-core.js`、`js/points.js`、`js/page-points.js`；服务端 `server/src/points.ts`）：每月按北京时间自然月送 50 积分（首次查看时到账，同月不重复）；¥30 → 600，¥60 → 1200 + 100。**充值是演示**：没有接入支付，不扣钱，界面在付款前说明并要求勾选确认；`POINTS_DEMO_TOPUP=false` 可关闭。余额存服务端，每笔一行流水，同一幂等键只记一次，余额不会扣成负数。本地体验账号用同样规则存在本机，并标明「只在这台手机上」。
- **价格**：冰箱贴 / 钥匙扣 5 积分，拼豆图纸与材料清单 5 积分，AI 照片生成 3D 20 积分，画廊作品由作者定价 0–50（默认 10），作者得 50%，手工捏泥免费。每次扣费前都有确认单，显示价格、现有积分和用后剩余。
- **拼豆**（`js/beads.js`、`js/page-beads.js`；服务端 `server/src/beads.ts`）：照片按 29 / 58 / 87 / 116 格取色（默认 58 格，即两块豆板宽；上限 128 格），每颗豆按约 4 个照片像素取平均，按 CIE Lab 匹配 32 色 5 mm 拼豆色号，可限制 8 / 20 / 32 色和过渡色。大图纸预览和存图会自动缩小每格尺寸，避免超出手机画布上限。解锁前预览是模糊的；解锁后有编号色卡、每色颗数、熨好后尺寸、豆板数，可存图、分享到画廊、下单邮寄。材料包价格由服务端按图纸计算（每色 1000 颗一袋 ¥6、豆板 ¥8、工具 ¥15、邮费 ¥8），**付款同样是演示**，订单记为「已付款（演示）」，管理端可改为打包中 / 已寄出并填快递单号。
- **捏泥**（`js/page-clay.js`、`js/clay-stage.js`、`js/clay-files.js`、`js/clay-projects.js`）：泥巴引擎**原样移植自团队的「捏个 PINCH」**（`mobile/pinch/core`、`mobile/pinch/geometry`，文件头注明来源），由 `mobile/pinch/along-clay.ts` 补上起手形状、网格转泥、视线拾取、撤销 / 重做和照片投影，`node mobile/tools/build-3d.mjs` 打包成 `js/vendor/clay.js`（35 KB）。四种起手形状（一团泥、圆泥饼、杯子、小房子），六种笔刷（堆、挖、抹、压、抓、刻），左右对称 / 拉坯 / 自由，六种泥色。手势：一指在泥上是捏、在旁边是转，双指缩放平移，另有「只转不捏」开关。照片可「从我看的方向」投影（背面不贴）或「绕一圈」包在杯子上。作品连同全部笔触存在本机 IndexedDB，重开完全一致。导出 GLB（带照片贴图）和 STL（毫米，可打印）。
- **AI 图生 3D**（服务端 `server/src/ai-models.ts`）：**已接入 OpenAI 兼容视觉模型**（`MESH_PROVIDER=openai-layout`，`MESH_LLM_BASE_URL` / `MESH_LLM_MODEL` / `MESH_LLM_API_KEY` / `MESH_LLM_ALLOWED_HOSTS`，只写在 `server/.env`，已被 git 忽略）。做法与 PINCH 的「照图搭粗模」一样：模型不输出顶点，只输出 3–16 个带颜色的基本体（球、方块、圆柱、圆锥、胶囊、圆环、棱柱），服务端按 PINCH `clean_layout` 规则清洗，手机端 `sceneFromLayout` 放到地面上、补出镜像件，转成按部件上色的泥，接着捏。实测一张豫园照片约 20–30 秒出 16 个部件。先扣 20 积分，失败、超时或被拒都自动退回一次。Tripo / Meshy 适配仍保留（`MESH_PROVIDER=tripo|meshy`）。本机开发服务默认不调用任何 AI；演示时用 `DEVELOPMENT_LOCAL_ALLOW_MESH=true npm run dev:local`，只会从 `.env` 读取 `MESH_*` 这几项。
- **文创画廊**（`js/page-gallery.js`；服务端 `server/src/gallery.ts`；管理端「文创画廊」「拼豆材料包」两个标签）：上传封面 + GLB（或拼豆图纸），先审核后公开；他人解锁一次即可下载和二创，作者可关闭二创；二创记录来源作品；作者可撤下。服务端检查 GLB 为单一静态网格、无外部链接和扩展。画廊里有 Along 自带的 10 件彩色示例（`js/gallery-examples.js`）：熊猫抱竹、红灯笼、三重小塔、一笼小笼包、珍珠奶茶、黄浦江轮渡 6 件釉色泥塑（部件配方，封面由泥巴引擎现场渲染，`js/clay-cover.js`），以及熊猫、灯笼、小笼包、外滩夜景 4 幅拼豆。它们排在旅人作品后面，离线或本地体验时也能看到；解锁后泥塑直接在工作台上打开、可以二创，拼豆直接进拼豆页。从工作台分享的彩色泥塑会带上部件配方（`recipe`，迁移 `006_clay_layout.sql`），别人二创时仍是彩色的；导出的 GLB 用顶点颜色保留每个部件的釉色。
- **界面**：牛皮纸积分袋、胶带贴着的纸卡、木框装裱的画廊、陶土色泥块；新图标都是 1.6 px 线稿，没有霓虹和发光。
- **需要部署**：画廊共享和 AI 图生 3D 需要把 `server/`、`005_workshop.sql`、`006_clay_layout.sql` 重新部署到 tokennext.top，并在线上 `.env` 写入 `MESH_*` 配置（迁移只新增表和列，不改旧数据）。部署前，线上 App 的积分、画廊、拼豆下单会提示连不上服务。
- 测试：`mobile/tools/clay.test.mjs`（引擎：闭合网格、撤销还原、对称、拾取、网格转泥、照片 UV）、`mobile/tools/workshop.test.mjs`（积分规则、拼豆取色与报价）、`server/test/workshop.test.ts`（每月赠送、演示充值幂等、不透支、拼豆订单、画廊审核 / 解锁 / 分成 / 二创权限、AI 未开通不扣分、失败退款、Tripo 协议与下载白名单）。

## 美食与住宿（2026-11-24）

行程不再只有景点：每天会推荐午饭、晚饭和当晚住哪，并估算这一天的花费。完整内容在新页面“美食与住宿”（`#/travel`），入口在“我”页、行程每天的“看全部美食与住宿”，也可以对小游说“美食”“去哪吃”“住哪”。

**依据的调研**（详细出处写在 App 的“订房和入住须知”里）：

- 佛山市消费者委员会《佛山市文旅消费调查报告》（2024，21 经济网报道）：餐饮满意度最低（82.53 分）；38.7% 的游客遇到菜价不合理，26.5% 遇到菜品不明码标价；住宿方面，三成遇到房价不合理上涨，24.8% 遇到预付后到店补差价或房型不符。
- 携程《2025 入境游调研报告》（百家号报道）：外国游客入住的三大痛点是支付不便、语言障碍和无烟楼层执行不严；特殊饮食（素食、无麸质）难以满足，菜单没有外文。另一篇报道列出的痛点是语言沟通、产品理解、行程衔接和突发情况处理。
- 百度百科「临时住宿登记」：住酒店由酒店登记；住在酒店以外，要在 24 小时内（农村 72 小时）向公安机关申报。

**做了什么**

- **按行程推荐吃饭**：每天的空闲饭点（午饭 11:00–15:00、晚饭 17:00–21:00）推荐一家餐馆，靠近当天景点的排在前面。行程里已经是饭点的站（静安晚餐、老门东小吃）会直接写明，不再重复推荐。只有一家餐馆符合忌口时，两顿都推荐它，并说明“暂时只核实了这一家”。
- **忌口与过敏筛选**：清真、吃素、不吃猪肉、不吃海鲜、花生过敏、麸质过敏、不吃辣。每道菜标注“适合你 / 先问一下 / 不适合”。清真只推荐清真餐厅；吃素在普通餐馆只能“先问一下”（可能共用锅、用猪油或肉汤）；花生和麸质因为油和酱油无法从菜名判断，一律“先问一下”。没选忌口时不显示标记。某城市没有对应餐厅时（上海暂无核实过的清真餐厅），直接说明，并给出地图搜索入口。
- **点菜卡**：把忌口写成大号中文给店员看，来华游客下面附英文；另附问价用语，比如“多少钱一份”“按份算还是按斤称”，对应调研里的菜价投诉。
- **城市必吃**：上海小笼、生煎、八宝鸭、素鸡素鸭；南京盐水鸭、鸭血粉丝汤、开洋干丝、素菜包，每道都写明推荐去哪家。
- **每晚住哪**：按当晚结束的地方和第二天的行程选住宿区域（上海：南京东路·外滩、静安寺；南京：新街口、夫子庙·老门东），可选经济型、舒适型、高档三档房价。第二天换城市时提醒“早上退房，带好行李”；最后一天提醒可以请前台寄存行李。
- **订房与入住须知**：付款前核对房型、早餐和免费取消时间，保存订单截图；节假日提早订；入住登记；无烟房；点菜先问价。国内游客看到的是身份证版本，来华游客看到的是护照版本。
- **每天花费**：门票（来自行程，准确）+ 饭钱 + 当晚房费（估算）合计成一个区间，并和每日预算比较（预算不含酒店，所以比较时也不算房费）。人民币填写的预算按原值显示（`budgetYuan`）。
- **适老版“今天”页**：下一站下面多了“下一顿饭”。
- **地图与小游**：餐馆和住宿区域都能点“导航”。和景点一样只用名字搜索，不使用未经核实的坐标。小游可以用餐馆名直接打开地图，比如“带我去马祥兴”。

**数据与局限**

- 7 家餐馆的地址、创办年份、是否清真或素食、招牌菜，都按百度百科词条核对过，每家都写了出处（`seed-food.js` 的 `source`）。营业时间和人均价格查不到可靠来源，所以没有填写；页面上的人均和房价都标注“估算”，是按价格档位写的参考区间，不是实时价格。
- 住宿区域的地铁线路按百度百科车站词条核对（`STAY_SOURCES`）。人民广场站没查到词条，改用已核实的南京东路站。
- 目前只有上海和南京两座城市，上海没有核实过的清真餐厅。
- 小游的服务端还不知道“美食与住宿”这个页面：AI 回答里不会出现这个入口，但直接说“美食”“住哪”会在手机上立刻打开（`LOCAL_ROUTES`）。
- 测试：`node --test mobile/tools/travel.test.mjs` 共 26 项全部通过；全量 `npm test` 共 422 项，唯一失败的仍是改动前就存在的 README 样例图用例；中英文案 1319/1319。浏览器预览里，国内游客和来华游客、中英两种语言、清真和素食筛选、点菜卡、三天行程、英文第 2 天、适老版“今天”页都实际走过，没有缺失文案或横向溢出。
- 测试包：`_build/Along-food-stays.apk`，签名、对齐和 AK 校验都通过，包内 170 个界面文件与源码逐字节一致。**尚未在真机上运行。**

## 国内游客与来华游客（2026-11-24）

App 不再只面向来华外国游客，国内游客也可以直接使用。“我 → 设置 → 我是”可在“国内游客 / 来华游客”之间切换，选择保存在本机（`along.audience`）。界面语言是另一项独立设置。

- **首次打开**：界面语言跟随手机系统语言，任何中文都显示中文界面，其他语言显示英文。手机语言为大陆简体中文（`zh`、`zh-CN`、`zh-Hans-CN`）时默认是国内游客；繁体、港澳台、新加坡中文及其他语言默认是来华游客。之后以用户保存的选择为准。
- **价格**：国内游客看到人民币，来华游客看到美元，参考汇率仍是 `FX_CNY_PER_USD`。金额照旧以整数美分保存；国内游客按人民币填写的每日预算会按同一汇率换算后保存。预约、刷卡和订单的数据结构没有变。
- **文案**：`messages/domestic.<语言>.json` 只覆盖已有的文案 key，用于国内游客。国内游客看到的是“什么时候到”“距离到达”，人民币预算，微信支付/支付宝、身份证实名预约、“见面时当面支付”等内容，银联排在卡种首位；来华游客的原有文案不变。`check.mjs` 会检查覆盖层只替换已有 key、中英两边一致、占位符相同。
- **中文内容**：`js/seed-zh.js` 给地点介绍、三天示例行程（标题、雨天方案、交通、提示）、三位伙伴（中文名、简介、擅长）和短片字幕补齐中文。中文界面下显示中文，英文界面下仍显示英文和中文地名；已保存的行程只有在仍是示例原文时才换成中文。小游可以用伙伴的中文名查找伙伴。
- **分享**：国内游客的短片分享用手机系统分享（壳里已有的 `Android.shareText`），不再引导打开 TikTok；话题是 `#旅行 #Along`。来华游客不变。
- **给司机看**：只在“国内游客 + 中文界面”时隐藏；用英文界面的人（包括在华外籍人士）仍保留。
- 测试：`node --test mobile/tools/audience.test.mjs` 共 21 项全部通过；全量 `npm test` 396 项，失败 1 项。这 1 项是改动前就存在的失败：`content.test.mjs` 把 `img/along-samples/README.md` 当成示例照片。中英文案 1243/1243，国内覆盖层 22/22。在浏览器预览里两种游客类型、中英两种语言都实际走过：行程、地点、伙伴、登录、预约结算、短片、分享、帮助、适老版“今天”页均正常，没有缺失文案或横向溢出。
- 测试包：`_build/Along-domestic.apk`（`--local-experience --api-base-url https://tokennext.top/along`），签名、对齐和 AK 校验通过，包内 164 个界面文件与源码逐字节一致。**尚未在真机或 Android WebView 上运行**，壳的系统分享也只核对了代码，没有在手机上点过。
- 尚未改动：服务端小游的系统提示仍写着“面向来华外国游客”，国内游客问小游时，它可能按外国游客的口吻回答；示例只有上海、南京两座城市。

## 当前运行与验收

先安装项目依赖、生成本地三维模块，然后在两个终端分别启动：

```text
npm ci
npm run build:3d
npm --prefix server ci
npm --prefix server run dev:local
node mobile/tools/serve.mjs 4175
```

- 网页：`http://localhost:4175`；管理端：`http://localhost:4175/admin/`。
- `dev:local` 使用易失内存数据库和本机私有文件，仅用于开发；显示的验证码不代表已发送邮件，严禁用于生产。管理员由显式 `ADMIN_EMAILS` 配置，不由用户提交角色。
- 真实网格：原图默认、人物区域凸起、背景平面；GLB 含纹理，STL 为毫米几何。没有 AI 凭据时可手工选择人物，明确标注非 AI；不伪造动漫图或人物分割。
- AI 编辑已实现官方 DashScope 协议；**仍须提供同时支持真人与动漫的可信人物分割服务**，普通 SegmentBody 不能替代动漫分割。
- 本轮测试：前端 **226/226**，服务端 **34/34**，中英文 **867/867**；真实本地 HTTP 联调 **64 项断言通过**，合成视频转码、封面和 Range 读取通过。

## 第二期做了什么

- 到达表单分两步：先填到达时间、城市、天数，再选兴趣、节奏、预算（选填）。
- "生成计划"：没有后端，所以填入的是产品种子数据里的示例计划（`generatedBy: TEMPLATE`），页面上有一行说明。兴趣、节奏、预算会保存，但目前不影响计划内容。
- 计划详情：天切换（点、左右键、左右滑）、时间轴、站间交通、雨天备选、费用合计、落地倒计时。计划保存在本机，刷新后还在。
- 营业时间检查：某站落在闭馆日或开放时间之外会标红提示。
- 地点弹层：照片与署名、中文名、停留、门票、开放时间、建议，"导航"和"给司机看"（全屏大字中文地名）。
- 首次打开的遮光板：上拉、点一下、按任意键或等 4 秒都会打开，只出现一次。
- 分享（复制行程文字）和"重新规划"（二次确认后删除本机计划）。
- `tools/build-seed.mjs`：从 `docs/03-种子数据.json` 生成 `js/seed-places.js`，地点数据不手抄。

## 第三期做了什么

- 向导详情页：月洞门头图、简介、语言与擅长、可约时段、安全说明、底部预约条。
- 登录弹层：邮箱 + 6 位验证码。规则按策划书：验证码 10 分钟有效，输错 5 次锁 15 分钟，同一邮箱每小时最多发 5 次。
- 结算页：票面（撕票线、状态印章）、价格明细、支付方式、取消政策。
- 预约状态：按策划书的状态机和时限（12 小时未确认过期、确认后 24 小时未支付过期、同一时段先到先得）。
- Trip 页的预约卡：状态印章、发消息、取消预约（二次确认）。
- 会话页：三句快捷句、发送文字。
- 帮助页：紧急电话、四个常见问题、联系人工入口。
- `tools/check.mjs`：检查中英文案是否一致、文案 key 和脚本引用是否都对得上。

**第三期全部是本机演示，没有接任何服务：**

- 登录不是真的身份验证：验证码直接显示在屏幕上，任何人都能用任何邮箱登录。
- 预约只保存在这部手机上，向导收不到。"代向导确认（演示）"按钮用来代替向导的答复。
- 刷卡支付不可选，只能选"当天付现金"。
- 消息只保存在本机，对方收不到；页面上有说明。
- 帮助页的"联系人工"没有配置联系方式，智能助手没有接入。
- 帮助页四个常见问题的答案和向导页的四条安全说明是我写的，需要产品核对后再用。

## 第四期做了什么

- 取景键的四个选项都接上了：拍照、做短片、做纪念品、发故事。
- 照片库：照片保存在本机，存入时长边压到 1920 像素以内。现提供 10 张示例照片（包含四张 Along 旅行演示照片），方便没有照片时试用。
- 选片页：点照片进入底部"胶片条"，顺序就是镜头顺序，可用前移后移按钮调整；3 到 12 张，三种风格，15/30/60 秒。
- 成片预览：9:16 画面，分段进度条，点左右半边切镜头，长按暂停；字幕编辑（最多两行、每行 32 字符）。
- 分享弹层：可翻面的拍立得卡片，配文加固定话题不超过 220 字符，复制配文，打开 TikTok。
- 文创页：选照片、产品、形状四步；按形状裁切照片并下载 1200×1200 的 PNG 数字版。
- 社区页：发故事（文字加照片），自己的帖子显示"审核中"并盖着长虹玻璃，可点赞和删除。

**第四期同样没有接任何服务，以下都不是真的：**

- "短片"只是手机上的照片轮播预览，没有生成视频文件，也没有配乐和旁白；"保存"按钮只提示尚未接入。
- 分享只能复制配文；没有视频可发，分享卡上没有二维码。
- 文创已有本机分层立体预览和作品库，导出仍是平面 PNG；未接云端建模、上链、实物下单或物流。
- 帖子只保存在本机，标着"审核中"但没有人审核，也看不到其他人的帖子。

## 第五期做了什么

- 适老版导航改为三项：今天 / 伙伴 / 求助，不再有取景键，通栏贴底。
- 适老版的"今天"页：只有下一站（大字时间、中英文地名、导航按钮）、向导预约卡、"拍一张照片"按钮；全天安排收在折叠区里。下一站会随当地时间推进。
- 适老版下"我"和"故事"不在导航里：求助页底部有"设置与账号"入口，"我"页里有"故事"入口。
- 离线横幅：断网时顶部提示，恢复后自动消失。
- 低端机降级：设备内存低于 4 GB 时，只有底部导航保留模糊，其余玻璃改为实色。
- 原生拍照接入照片库：App 里拍的照片通过 `window.onNativePhoto` 进入新照片库，只接受 App 自己照片目录下的地址。

- 成片预览页补了页面标题。
- 无障碍巡检：11 个页面和 6 个弹层逐一检查了按钮名称、输入框标签、图片替代文字、重复 id、标题层级和弹层焦点。

**第五期里没有验证或没有做到的：**

- 原生拍照接入是照着旧 App 的代码写的，只用模拟数据测过，没有在真机上跑过。
- 离线只做了横幅。没有做离线缓存（Service Worker）；目前所有数据都存在本机，所以断网时页面本来就能用，但这不等于策划书要求的 PWA 离线缓存。
- 低端机降级只按设备内存判断，没有做方案里写的帧率检测；用模拟的内存值测过，没有在真的低端机上试。
- 无障碍巡检是脚本检查，没有用读屏软件实际听过。
- 没有做：每个手势的按钮替代全量核对、系统"减少透明度"设置的实测、WebView 兼容性实测。
