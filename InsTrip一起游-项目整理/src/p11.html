09 / ARCHITECTURE · 技术架构
HOW IT IS BUILT

两端一线：
应用、展示站与内容管线。

客户端负责随身的行程与记录，展示站负责把作品与理念讲清楚，内容管线把照片变成可以转起来的三维纪念。三者共享同一套内容与口径。

交付层DELIVERY
Android 应用 v2.7.0Web 静态展示站Windows 一键启动器零依赖本地预览服务静态部署（Nginx / 宝塔）
体验层EXPERIENCE
首页与每日行程地图与路线规划志愿向导与消息同城社区与城市故事数字藏品与照片回忆旅行短片与旅行文创三维记忆馆
能力层CAPABILITY
百度地图 SDK（地图 / 步行路线）天气与在线地点数据CameraX 相机与相册AI 对话与插画生成Lux3D 云端建模浮雕几何加工three.js / WebGL
内容层CONTENT
44 份主题档案12 件 GLB 文创 + 模型清单南京实景（附原图与许可）9 张应用截图MiSans 字体
质量层TRUST
sha256 文件清单三态状态标注失败降级与重试素材来源与许可留档减少动态效果 / 键盘可达

技术栈速查

客户端Android 原生（Kotlin）外壳 + WebView 页面层；百度地图 SDK、CameraX
云服务社区、同行伙伴、会话消息、短片任务、行程与客服接口
展示端原生 JavaScript（无前端框架）+ three.js；CSS 玻璃拟态
三维glTF Binary（GLB）、参数化浮雕建模，mm 记录尺寸

一条数据，怎么走完全程

照片（相册 / 相机）→ 插画示意（AI 风格化）→ 云端网格（Lux3D）→ 浮雕加工（闭合背面、挂孔或磁贴）→ 几何校验 → GLB → WebGL 展陈（360° 观察、拆开看故事、下载）

取舍：展示端刻意不用前端框架，换来更小的体积、更少的依赖。
